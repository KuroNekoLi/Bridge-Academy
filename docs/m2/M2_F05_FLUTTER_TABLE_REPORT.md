## Safety / known exclusions

- Widgets receive PlayerView only; all actions remain Bridge Core-authorized.
- Declarer controls Dummy after lead; 4x Pass Out and normal scoring from Core.
- Demo Bot is a fixed rules placeholder and always visibly labeled NOT BEN.
- Real BEN mode uses actual HTTP; exceptions do not silently switch to demo.
- BEN GET URLs contain the bot's authorized hand: restrict host/logging and
  use a trusted proxy/HTTPS for any remote deployment.
- This is a local in-process single-player MVP: the Flutter runtime holding SinglePlayerCoordinator still contains the complete deal in process memory. PlayerView prevents Widget-level exposure and protects BEN requests, but does NOT provide anti-cheat secrecy against someone inspecting or reverse-engineering their own client. Multiplayer/competitive fairness requires server-side deal authority.
- Platform scaffolds generated by flutter create, not tracked. Native builds,
  voice-over accessibility, mobile QA, random deals, persistence, UX polish,
  real BEN UI clicks and app-store signing remain OUT OF SCOPE.
